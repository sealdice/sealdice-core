# 自定义回复 VM V1/V2 语法兼容性分析

本文基于 sealdice-core `5da66c91` 的 V1 RollVM，以及当前依赖的
`github.com/sealdice/dicescript@c4c99fe00cb6`（V2）进行对照。范围只包括两版都具备、
但语法或行为不同的能力；数组、字典、浮点数、函数、循环等 V2 独有能力不在本文展开。

## 文件版本规则

- 文件首行是 `# sealdice: vm-version=v2`，或顶层字段是 `vmVersion: v2` 时，固定使用 V2。
- 两个声明都没有时，不强制判为 V1，而是继续使用全局 `VMVersionForReply`。
- V2 文件保存时同时写入首行注释和 YAML 字段。注释便于人读，字段用于抵抗普通 YAML
  工具重写时丢失注释。
- 当前“转换为 V2”只写入版本声明，不自动改写表达式，因此必须保留不兼容警告。

## 共有语法的实际差异

| 范围 | V1 | V2 | 迁移结论 |
| --- | --- | --- | --- |
| `\|\|` | 与 `\|` 一样执行按位或。例如 `1 \|\| 2` 得到 `3`。 | 逻辑或，短路并返回操作数；`1 \|\| 2` 得到 `1`。 | 不能静默兼容。转换器必须提示并要求确认语义。 |
| `&&` | 与 `&` 一样执行按位与。 | 返回逻辑操作数，但当前实现仍会先求值右侧；`0 && (1/0)` 两版都会报错。 | 采用 V2 的逻辑含义，不保留 V1 的按位含义；不要宣称当前 `&&` 会短路。 |
| `&`、`\|` 优先级 | 两者处在同一层并从左到右计算；`1 \| 2 & 4` 得到 `0`。 | `&` 优先于 `\|`；同一表达式得到 `1`。 | 不保留 V1 优先级。转换器应按 V1 AST 补括号。 |
| 字符串比较 | `==`、`!=` 可用；`< <= > >=` 会进入有缺陷的整数比较路径，甚至生成“字符串类型、整数值”的非法结果。 | `==`、`!=` 可用；字符串不支持顺序比较并明确报类型错误。 | 只保留字符串相等/不等；顺序比较一律报错。 |
| 一元 `+` | 对字符串也是无操作，`+'x'` 得到 `'x'`。 | 只接受数字，字符串会报类型错误。 | 不保留字符串一元加号。 |
| 全角算符 | 支持全角四则运算和 `＜ ＞ ＜＝ ＞＝ ＝＝ ！＝`。 | 仍支持全角 `＋ － ＊ ／`，但比较算符只接受 ASCII。 | 建议在兼容词法层保留全角比较符到 ASCII 的规范化。 |
| HTML 转义算符 | 语法中接受 `&amp;`、`&amp;&amp;`，但会与 `&` 和分号产生脆弱、反直觉的解析结果。 | 不接受这些写法。 | 不作为 VM 运算符保留；只在明确来自 HTML 的导入阶段做实体解码。 |
| 多语句分隔 | 简单语句之间依赖 `;`；换行通常只是空白。 | 接受 `;`，也可把换行作为语句边界。 | 共同的稳定写法是 `;`，无需为 V1 另设执行语义。 |
| `//` 注释 | 注释属于空白，可出现在运算符之间或语句尾；`1 + //x\n2` 可得到 `3`。 | 注释主要作为独立语句处理；同一例子只解析出前缀 `1` 并留下未消费输入。 | 建议兼容解析器按词法规则保留行内注释，不能用不区分字符串的正则删除。 |
| `if` 空格 | `if` 后可不留空格，例如 `if1{...}` 会尝试按 `if 1 {...}` 解析。 | `if` 与条件之间必须至少有一个空白。 | 不保留无空格写法；转换检查器给出可自动修复的诊断。 |
| `int()`、`str()` | 内置语法名称是 `int(expr)`、`str(expr)`。 | 对应函数名是 `toInt(expr)`、`toStr(expr)`。 | 建议在 V2 兼容层保留两个旧名称的函数别名，或由转换器结构化改名。 |
| 模板插值 | 反引号模板除 `{expr}` 外，还接受 `{{expr}}`；例如 `` `{{1+1}}` `` 得到 `2`。 | 接受 `{expr}` 和 `{% statements %}`，不接受双花括号别名。 | 可在 V1 来源明确时把 `{{expr}}` 重写成 `{expr}`；不建议长期扩展 V2 主语法。 |
| 前导下划线变量 | 读取变量时会剥掉全部前导 `_`，所以 `_hp` 会读取 `hp`；这还会让赋给 `_hp` 的值难以按原名读回。 | `_hp` 与 `hp` 是两个正常、独立的变量。 | 明确不保留。转换检查器应将此列为高风险项。 |
| 标识符范围 | 使用排除式字符表，且没有可靠的保留字约束，能吞入一些非标准名称。 | 使用 Unicode 标识符规则，并保留 `if/else/while/continue/break/return/func`。 | 保留常规中英文、数字后缀、`_`、`$`、冒号；不保留任意标点和关键字变量名。 |
| `b/p/f` 与变量 | 词法边界较弱，名称以 `b`、`p`、`f` 开头时可能先被当作奖励骰、惩罚骰或 Fate 骰并留下尾部。 | 有明确边界，普通标识符不会被骰子前缀抢占。 | 明确不保留 V1 的前缀抢占；转换器应报告有歧义的旧表达式。 |
| `kh/kl` | 裸写在一元骰后是“优势/劣势”别名：`d20kh` 实质为 `2d20k1`，`d20kl` 实质为 `2d20q1`。 | 是通用 keep-high/keep-low 后缀；`d20kh` 只是在一个 d20 中保留一个，不再表示优势。 | 不能在 V2 中保留旧含义。对 V1 来源精确重写为 `2d20kh1` / `2d20kl1`。 |
| 多个保留/丢弃后缀 | 可按固定顺序叠加 `k`、`q`、`dl`、`dh`，后写项会形成难以解释的组合状态。 | 一次只接受一个主要保留/丢弃后缀。 | 不保留组合后缀；要求作者拆式或选择唯一意图。 |

## 建议保留的兼容能力

这些兼容项语义明确、实现成本低，适合未来在 V2 兼容模式中继续支持：

1. 全角比较算符到 ASCII 的词法规范化。
2. `int()` 到 `toInt()`、`str()` 到 `toStr()` 的函数别名。
3. V1 模板中 `{{expr}}` 到 `{expr}` 的结构化转换。
4. 表达式中的 V1 行内 `//` 注释，但必须由词法器处理并避开字符串内容。
5. 明确来自 V1 文件时，将一元骰后的 `kh/kl` 重写为无歧义的优势/劣势表达式。

## 不建议保留的历史行为

以下行为会污染 V2 的可预测性，应由诊断和人工确认处理，而不是继续塞进解释器：

1. 把 `||`、`&&` 当成按位运算。
2. `&`、`|` 同优先级的 V1 计算顺序。
3. 字符串顺序比较产生非法内部值。
4. 字符串一元 `+`。
5. 读取变量时剥除前导下划线。
6. `b/p/f` 无边界地抢占普通变量名。
7. 多个 `k/q/dl/dh` 后缀叠加。
8. 在 VM 语法中直接接受 `&amp;`、`&amp;&amp;`。

## 转换检查建议

未来若实现真正的自动转换，不应只做全文字符串替换。至少要对表达式和模板插值建立词法/语法节点，
然后对以下模式给出分级诊断：

- 阻断转换：`||`、`&&`、混合 `&`/`|`、字符串顺序比较、组合骰子后缀。
- 可自动修复：`int/str`、全角比较符、双花括号模板、无空格 `if`、一元骰 `kh/kl`。
- 需要人工确认：前导下划线变量、非常规标识符、`b/p/f` 前缀歧义、HTML 实体算符。

当前按钮只负责把文件锁定为 V2，因此其确认提示“不会自动改写表达式，可能不兼容”是必要的，
不能把该操作描述成已经完成语法迁移。
