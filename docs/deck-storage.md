# 牌堆压缩存储

牌堆源文件是事实来源，缓存可以删除和重建。本地正文使用 mmap 文件中的独立 zstd 块，分块上限为 **256 条或约 16 KiB 未压缩载荷**，先到者为准；合法超长单条独占一块。压缩采用已有的 klauspost zstd SpeedFastest，window 为 128 KiB；window 与目标分块大小是不同参数。

Go 长期保留业务元数据、公开命令及每组 16 bytes 的哈希目录。组描述、原 key、块索引、累计权重和压缩正文位于映射文件；哈希命中后比较原 key，碰撞不能当作相等。抽取先选下标，再解压对应块，内部引用保持运行时递归。

全局解压缓存预算为 4 MiB，按保留 byte slice 的容量计数，不包含 map/list 节点、解码器、返回字符串、映射驻留页和上下文不放回池。超过预算的单条照常解压，但不进入缓存。权重直接读取映射，没有额外的解压权重缓存。RSS 还包含映射页和 Go 尚未归还操作系统的页。

## 一致性与生命周期

一次顶层抽取固定一个不可变目录快照，所有递归和跨牌堆抽取使用该快照。重载、启停和更新在写锁下准备并发布新目录；旧读者结束后释放旧映射。上下文不放回池按目录版本失效，不能用旧下标访问新组；块缓存以存储对象及块偏移区分版本。存储锁只保护读取、解码和回收，不覆盖格式化、递归或网络请求。

在线更新先解析和构建新存储，在源文件同目录写入临时文件并成功替换源，再提交缓存 meta、发布目录。源替换失败保留已发布版本；meta 提交失败有日志，下次从源重新导入。Windows 的文件替换不承诺与 Unix 相同的断电原子性。

持久缓存位于骰子数据目录的 `cache/decks`。meta 保存来源标识、扩展包归属、源/缓存 SHA256 与长度、解析版本、格式版本、编码/分块参数、统计及业务元数据。未变化重载与二次启动可恢复，仍会校验源和缓存内容；不只是检查 mtime。完整重载清理已删除来源及孤儿文件，包括删除最后一副牌堆。正常关闭保留有效缓存。

缓存目录持有 OS 文件锁，避免进程间清理仍被使用的映射。目录争用、写入或映射失败时记录原因，依次使用临时 mmap、原全内存方式。临时文件在旧读者全部结束后释放。格式损坏的重载保留当前进程已发布的有效版本。

## 兼容性与取舍

继续使用原解析器处理 JSON、JSONC、YAML、TOML、无扩展名和 BOM；保留文件名回退、命令导出、私有组、StoreID、包归属及安装状态。默认权重与显式零权重区分，权重不窄化为 uint32。权重预计算避免旧版每次放回抽取扫描整组、重新编译正则及构建选择器，因此完整抽牌速度变化不能全部归因于存储方式。

云牌仍按原语义合并、去重和处理网络失败；其本地基底会临时展开，云牌上下文池仍可能持有正文。源解析仍整体保留一副牌堆，导入内存为 O(单副牌堆大小)，没有声称为有界流式解析。没有主动强制归还运行时内存。

基准代码、数据来源、原始记录和比较报告单独保存在 [sealdice-deck-benchmark](https://github.com/sealdice/sealdice-deck-benchmark)。正式实现没有 SQLite 比较后端、FSST、字典训练或实验环境开关。历史基准测量的是固定实验快照；正式分支的检查另行执行，不将历史数值冒充本分支重新测量。
