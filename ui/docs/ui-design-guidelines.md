# SealDice UI 设计指南

本文档用于约束 SealDice V2 管理界面的视觉与交互设计。它描述设计判断的共同基准，不替代组件 API、业务需求或无障碍规范。

## 设计目标

SealDice UI 应当现代、优雅、清晰，同时保持克制。界面首先服务于管理、配置和排障，不通过额外装饰制造“设计感”。

设计时按以下顺序判断：

1. 信息和操作是否清楚、准确；
2. 相同概念是否保持一致；
3. 视觉层级是否足够，但不过度强调；
4. 动效和装饰是否确实改善理解或反馈；
5. 深色、浅色、不同尺寸和无障碍场景是否同样可用。

## 视觉语言

### 扁平化，但保留层次

- 不使用拟物高光、厚重投影、浮雕或无意义的渐变边框。
- 优先通过背景层级、间距、细边框和排版建立层次。
- 阴影仅用于弹窗、浮层、下拉菜单等确实高于页面的元素，不应成为所有卡片的默认装饰。
- 避免多层卡片嵌套。页面、分区、内容通常不应超过三个视觉层级。
- 留白用于分组和引导视线，不用于单纯扩大界面。

### 统一且克制的颜色

- 全局只维护主题、成功、警告、失败四种有彩基础色。背景、文字、边框使用集中定义的中性色阶。
- 主题色用于主要操作、当前状态和必要的视觉焦点，不应铺满大面积背景。
- 成功、警告、失败色只用于对应状态，不能作为普通操作或分类标签的装饰色。
- 组件 API 中的 `info` 是兼容语义，统一映射到主题色及其浅色衍生色，不构成第五种基础色。
- 浅色背景、选中态、边框和悬浮态由上述颜色或中性色阶集中衍生，不允许用户分别调整页面背景等局部颜色。
- 优先使用低至中等饱和度，通过明度和对比度表达层级。
- 颜色必须来自主题变量；不要在页面或组件中临时硬编码新的品牌色、背景色和边框色。
- 深浅主题应表达相同的层级关系，而不是简单地将颜色反相。

### 适度的小圆角

- 圆角用于减弱生硬边缘，不用于把所有元素做成气泡或胶囊。
- 微型标记与紧凑元素使用 `--sd-radius-xs`（`4px`），按钮、输入框和导航项使用 `--sd-radius-sm`（`6px`），卡片、面板、工作区和弹窗使用 `--sd-radius-md`（`8px`）。
- 标签和状态标识可以使用更小的圆角。只有头像、圆形按钮或明确具有胶囊语义的元素才使用完全圆角。
- 同一层级、同一类型的组件必须保持一致的圆角。

### 边框与阴影

- 分隔优先使用低对比度的 `1px` 边框或背景差异。
- 不要同时使用高对比边框、强阴影和明显背景色强调同一个元素。
- 页面背景、普通卡片、预览区和工作区默认不使用装饰性渐变或阴影；通过背景层级与边框表达结构。
- 深色主题中的边框应清晰但不发亮；浅色主题中的阴影应轻，不制造悬浮卡片堆叠感。

## 信息层级与文案

### 充分利用标题的自解释性

页面标题、分区标题、弹窗标题、字段标签和按钮名称应直接说明对象或动作。标题已经表达清楚时，不再添加一句同义的副标题或 caption。

- 普通管理页面的主标题必须与侧边栏当前项和面包屑中的页面名称一致。关于页等品牌展示页可以使用产品名称作为唯一主标题，不重复显示导航名称。
- 通用 `PageHeader` 只承载页面主标题和页面级操作，不提供固定描述区域。
- 必须保留的风险、格式、范围、数据来源或操作后果应放在对应控件、操作或内容附近，不放在页面标题下充当常驻简介。

不推荐：

- 在“网络日志”下补充“查看网络日志和连接状态”；
- 在“示例状态”下补充“查看示例状态”；
- 使用“在这里管理……”“你可以在这里……”填充标题下方的空白；
- 为每个分区固定放置一行灰色说明文字。

辅助说明仅在下列情况下使用：

- 操作存在不可逆后果、安全风险或数据丢失风险；
- 输入格式、单位、范围或限制无法从标签和控件中得知；
- 当前状态、数据来源或生效范围容易产生误解；
- 新概念缺少用户熟悉的界面惯例，确实需要首次解释。

说明应尽量出现在用户需要它的位置：字段约束放在字段附近，错误原因放在错误位置，按钮解释可使用悬浮提示，空状态说明只出现在空状态中。不要用常驻 caption 提前解释所有可能情况。

### 排版

- 一个页面只设置一个明确的一级标题。
- 普通页面一级标题统一使用 `--sd-page-title-*` 变量，不在页面内自行放大或改变字重；品牌展示页可按独立规范处理。
- 标题应简短、具体，通常不使用句号，不写成宣传语。
- 通过字号、字重和间距建立层级，避免依靠多种颜色和大量粗体。
- 正文保持稳定的行高和阅读宽度；日志、代码、标识符等技术内容按需使用等宽字体。
- 弱化文字仍需满足可读性要求，不能把低对比度当作“高级感”。

### 中西文混排

中西文之间的间距由渲染层承担。`base.css` 在 `body` 上声明 `text-autospace: normal`，浏览器按 [CLREQ](https://www.w3.org/TR/clreq/) 补入四分之一汉字宽的间隙。它不写入文本内容，复制、搜索和 `textContent` 都不会带上多余空格，也会自动覆盖中文与行内代码块、`n-tag` 之间的边界。

- 新增文案不手写中西之间的空格，交给 `text-autospace`。
- 存量文案中已有的空格保留，不专门清理。半角空格约 0.32 个汉字宽，与自动间距不叠加，两者差异不足 1px，改写的收益不足以抵掉触及测试断言的风险。
- 以下位置 CSS 不生效，仍需手写空格：原生 `title` 属性（由系统绘制）、导出文件的文件名与内容、`document.title`、写入剪贴板的文本。
- 等宽块（`pre`、`kbd`、`samp`，以及 `.sd-code-text` 下的输入框与 `pre`）关闭自动间距，避免破坏按字符对齐。只关容器内部：不要给行内 `code` 本身声明 `no-autospace`，那会连带取消它与前后中文之间的边界间隙，而该间隙正是需要保留的。

### 标点

正文使用全角标点：`，。、；：？！（）「」——……`。自动间距只处理间距，不处理标点，因此标点必须在文本里写对。

- 中文语境中的括号、冒号、引号一律用全角。半角括号仅用于西文短语内部。
- 引用界面元素名称、分组名、筛选条件或用户输入的值时统一使用 `「」`，不使用 `""` 或 `“”`。弯引号 `“”` 在界面字号下容易被误认成半角，且与全站 `「」` 惯例不一致。字面量优先包成行内代码块，`「」` 用于无法使用代码块的场合。
- 全角标点自带左右空隙，两侧不再补空格。
- 并列取值之间用全角中点 `・` 分隔（如运行环境 `linux・amd64・容器模式`），不用 `-`、`/` 或两侧带空格的 `·`。中点已自带空隙，不再补空格。数据格式中的分隔符不适用本条，见「技术字面量」。

### 技术字面量

海豹码、豹语变量、骰子指令、导出格式等字面量有确定语法，排版规范不适用，也不允许自动工具改写。

- 这类内容包进行内代码块（`n-text code` 配 `sd-code-text`，或 `n-tag`），语义正确且天然排除在排版规则之外。
- 常见字面量：海豹码 `[图:路径]`、豹语变量 `$tQQ昵称`、骰子指令 `.rd`、回声工坊导出格式 `<dice>:`。其中的半角冒号是后端解析依据（见 `message/message.go`、`dice/im_vars.go`），改成全角会直接失效。
- 数据格式中的分隔符不是标点。回声工坊导出的逗号是 CSV 字段分隔符，中文列表里的顿号才是标点，两者不能互换。
- 纯文本插值（如只接受 `string` 的选项说明）无法使用代码块时，用 `「」` 包裹字面量。

## 布局与组件

### 页面与分区

- 相关内容靠近放置，不相关内容通过间距或分隔线区分。
- 页面级操作保持在稳定位置；同一区域通常只保留一个主要操作。
- 不要因为需要一个边界，就把每个分区都包装成卡片。可以使用留白、标题和细分隔线完成分组。
- 表格、日志、配置表单等高密度内容应优先保证扫描效率，不强行扩大行高或增加装饰。

### 设置组的父子层级

- 仅当多个字段确实从属于同一个可命名设置组时，使用“父标题 + 子面板”结构；普通编辑表单、列表工具栏和连续任务流程不应机械套用。
- 设置组标题位于面板外，使用统一的较高字重。标题旁可以放置控制整个设置组的开关或紧密相关操作，不把组级开关推到远离标题的容器另一端。
- 一个设置组只使用一个整体子面板。子字段集中放在面板内，不为每个字段分别套卡片或气泡。
- 子面板使用 `--sd-bg-elevated`、`--sd-radius-md` 和统一内边距建立从属关系；默认不使用阴影、主题色边框或大面积主题色，也不再叠加明显的整体缩进。
- 子面板的内边距以可见控件为基准保持上下对称。中间行始终保留表单反馈高度，出现校验信息时不得推动后续字段；最后一行没有校验消息时，不计入空反馈区的预留高度，出现反馈时只使子面板下边缘自然扩展。
- 字段标签维持正常字重，通过面板关系、字段间距和排版区别于父标题。不要仅靠字号差异或额外颜色表达父子关系。
- 父级开关关闭时，隐藏其控制的整个子面板，但保留该设置组与相邻设置组之间的正常间距。
- 桌面端可在子面板内使用适量分栏；窄屏下必须回落为单列，并缩小面板内边距，不能依赖固定缩进表达层级。
- “综合设置 → 基本设置”中的设置组是该模式的视觉基准。所有具有父子层级的设置组必须通过 `SettingCategoryBox` 进入统一框架；字段布局、响应式分栏和尾行反馈规则由其内部的 `SettingFieldLayout` 承载，页面不得重复实现。
- 设置组内的说明与提示放进 `#notes` 插槽，由容器统一提供与字段一致的左右内边距；不要让提示紧贴子面板边缘，也不要在页面里给单个提示补 margin。
- 参数、数据展示与危险操作各自独立成组时，仍按设置组处理。只有存在强制顺序、阶段状态或前进后退控件的流程才算向导，不能因为面板从上到下阅读就套用向导结构。

### 竖直节奏

- 普通页面使用 `sd-page-flow`，页面标题、前置提示、标签选择器、设置组、工具栏和主内容之间统一使用 `--sd-space-md`（`16px`）的页面分区间距。
- `PageHeader` 只负责标题本身的下边框和内边距，不自行添加外边距。标题与首个内容元素之间的距离由页面容器统一提供，不能因为首元素是标签页而额外增加 `margin-top` 或 pane margin。
- 同一业务分区内部的纵向元素使用 `sd-section-flow` 或对应公共组件，同样以 `--sd-space-md` 为默认间距；控件内部、同一行字段和紧密相关的元信息才使用 `--sd-space-xs`／`--sd-space-sm`。
- 筛选器、列表面板和分页共同构成一个列表工作区，必须通过 `ListWorkspace` 保持 `16px` 间距。两个各自带圆角或边框的相邻区域不得零间距贴合。
- 标签页面板的首个内容与标签导航保持一个页面分区间距；禁止用 `pane-class="mb-*"`、页面特例 margin 或空元素制造间距。
- 特殊工作区（聊天、代码编辑器、全屏预览）可以使用自己的内部布局，但它作为页面首个内容时，仍遵守标题后的统一间距。

### 可添加多子项的设置

一个设置下可添加多个同级编辑项时，统一使用 `RepeatableList` 和 `RepeatableItem`。标签输入、单纯多选和只读业务列表不是此模式。

- 子项按单列自上而下排列，间距为 `--sd-space-sm`。每项使用低对比细边框、`--sd-radius-sm`、`--sd-bg-elevated-soft` 和对称内边距，不再混用无边界行、标签气泡和重卡片。
- 添加入口固定在全部子项下方左侧，使用带 `plus` 图标的主题色浅底按钮（`type="primary" secondary`），文案为「添加…」。不把添加按钮放在首项左侧、某一项右侧或使用单独的圆形加号。
- 删除入口固定在子项标题栏右侧末端，使用 `trash` 图标的红色四级圆形按钮。仅图标按钮必须有 `aria-label` 和悬浮说明；不混用叉号、减号和「删除」文字按钮。
- 子项启用开关位于同一标题栏右侧、删除按钮之前。开关只控制当前子项，使用全站滑动开关规范；不能放在内容字段之间或子项最左侧造成与选择控件混淆。
- 拖动手柄、折叠、重置等子项级辅助操作与开关、删除按钮同属右侧操作区；顺序为「拖动／辅助操作、启用、删除、折叠」，危险操作与普通操作保持视觉区分。
- 子项没有可命名标题时仍保留顶部操作栏，可用「第 N 项」作为可访问且可扫描的标题。窄屏下操作栏可换行，但删除入口仍保持在右侧操作区。
- 至少保留一项的业务应禁用最后一项的删除按钮，而不是把首项改造成添加按钮。空集合使用空状态并在其下保留同一个添加入口。
- 紧凑字符串集合若值本身就是短标签，可使用可关闭标签配合底部「添加…」按钮；其添加和删除语义、颜色、图标仍遵守以上规则。

### 列表与筛选

- 页面级结果集合统一由 `ListWorkspace` 组织，可选顺序为：`QueryToolbar` → `ListActions` → `ListPanel`（内部可含 `ResultToolbar`）→ 分页。没有筛选器或列表操作时直接省略对应区域，不保留空壳。
- `QueryToolbar` 是筛选和搜索的唯一容器，使用统一圆角、边框、浅层背景和内边距。查询为主按钮，重置为中性按钮；筛选器不能与列表面板合并圆角或紧贴。只有一个筛选项时，桌面端允许该字段与重置、查询按钮同行，窄屏仍回落为单列。
- 筛选表单的中间行保留空反馈区作为稳定行距，只有当前视觉尾行的空反馈区折叠；真实校验反馈始终保留。这样首行和尾行到容器边缘的距离对称，同时不会压缩多行字段之间的竖直间距。
- `ListPanel` 是结果边界，始终使用 `--sd-radius-md`、`1px` 低对比边框和 `--sd-bg-elevated`。表格、卡片列、树和紧凑移动列表均置于其中；页面不得再为同类结果手写一套圆角。
- 已知总数时，在 `ResultToolbar` 左侧统一显示「共 N 项」；存在选择时紧随其后显示「已选 N 项」。总数未知时不显示估算值，也不为了视觉对称写「当前页 N 项」。
- 批量操作只在有选择时启用或显示，位于结果工具栏右侧。列表数据创建／导入等操作属于 `ListActions`，不混入结果摘要。
- 分页只属于“当前结果是完整集合的一部分”的列表：已知总数超过每页数量、游标接口明确存在下一页，或当前已经位于第二页及以后时显示。空的第一页和仅一页结果不显示分页；第二页以后即使因筛选或删除暂时为空，也保留分页以允许返回。一次性加载完整集合的列表（如本地筛选后的已安装扩展包、备份文件）无论有无内容都不显示分页。
- 分页位于列表面板下方并右对齐，窄屏左对齐；页码和每页数量选择器作为同一控件出现，分页与列表仍由 `ListWorkspace` 提供统一间距。游标接口不得伪造业务总数，只可用当前页位置和“存在下一页”构造导航所需的最小哨兵数量。
- 无数据、加载和失败状态占据 `ListPanel` 的结果区域，不能让筛选器或分页代替结果边界。桌面表格与移动紧凑视图使用 `ResponsiveDataView` 保持功能等价。
- 允许例外：编辑器内部的短候选菜单、导航树、下拉选项和纯展示统计不属于页面级结果列表，不强制套用 `ListWorkspace`／`ListPanel`。

### 按钮与操作

- 同一操作区域通常只有一个主按钮，其余操作使用次要、文字或图标样式。
- 同一操作区域默认横向排列按钮，并保持统一间距；仅在可用宽度不足时换行，不把可并列的操作固定为每行一个按钮。
- 操作区域与其上下相邻的筛选区、列表或面板使用统一的页面分区间距，不能紧贴内容边缘。
- 同类页面按业务流程统一按钮顺序。资源管理场景优先排列“获取”，随后排列“上传”；创建、导入、导出等并列操作保持“创建或添加、导入、导出”的顺序。
- 影响整个模块、运行状态或多个标签页的操作放在页面标题右侧，例如启用、重载和全局刷新。
- 创建、获取、上传、导入和导出等列表数据操作放在列表操作栏左侧；刷新当前列表、设置和选择后批量操作放在列表操作栏右侧。
- 上述左右位置表达操作的语义锚点。窄屏下允许两组自然换行，不以维持绝对位置为代价压缩按钮或造成横向滚动。
- 执行当前页面核心任务的操作使用主题色实心主按钮，例如查询、保存、确认，以及作为页面主要操作的刷新或重载。
- 创建或引入数据的次要操作使用主题色浅底按钮，即 `type="primary" secondary`，例如添加、导入、上传和获取资源。
- 不改变业务数据的辅助操作使用默认中性色按钮，例如刷新预览、重置筛选、导出、复制和下载。刷新仅在承担页面主要操作时使用主题色实心样式，不能仅凭“刷新”文案决定颜色。
- 同一入口同时承载导入和导出时，入口本身使用默认中性色；进入弹窗后，导入或确认操作使用主按钮，导出仍使用默认按钮。
- 成功色和警告色不用于普通操作按钮，只表达已经成功或需要警惕的状态。
- 危险操作应明确标识，并在后果显著时要求确认。
- 仅图标按钮必须提供可访问名称和悬浮提示。
- 带有清楚文案的按钮不需要为了装饰而附加图标。
- 可见文案已经完整说明内容或操作时，不再添加同义或相同的悬浮提示。悬浮提示仅补充图标语义、被截断内容、精确值、格式限制、作用范围或操作后果等不可直接得知的信息。
- 同一元素不能同时使用组件悬浮提示与原生 `title` 重复显示相同文案。

### 表单

- 字段标签直接说明输入内容；占位符用于示例，不替代标签。
- 仅在约束不明显时提供辅助说明。
- 校验错误靠近对应字段展示，并说明如何修正。
- 相互依赖的字段应在布局和交互上体现关系，避免让用户自行推断。
- 文案较短且同属一组的复选框或单选项优先按内容宽度横向平铺，并在空间不足时自然换行；不强制使用单列或无必要的等宽网格。

### 弹窗

- 标题明确说明当前任务，正文只包含完成任务所需的信息。
- 底部操作保持简洁且顺序一致，一般将确认操作放在右侧。
- 弹窗内通常只有一个主要操作；取消操作不应与确认操作争夺视觉焦点。
- 不在弹窗底部添加与内容无关的彩色圆角背景块、提示气泡或装饰性区域。

### 标签与状态

- 标签用于分类或状态，不用于填补空白和增加色彩。
- 同一状态在全局使用相同颜色、图标和文案。
- 颜色不能成为区分状态的唯一方式，应同时提供文字或图标语义。

## 提示与状态反馈

提示信息的混乱几乎总是来自把三件独立的事塞进一个组件参数里。设计时必须分开决定三个维度，它们各自取值，互不推导：

- **语义**决定**颜色与图标**；
- **行为**（这条信息何时消失）决定**载体**；
- **信息与其对象的距离**决定**位置**。

"warning 色"不意味着"顶部横幅"，"顶部横幅"也不意味着"warning 色"。

### 语义决定颜色与图标

只有四种语义，映射到既有的四个基础色，不新增第五种。

| 语义      | 含义                         | 颜色变量                             | 图标                      |
| --------- | ---------------------------- | ------------------------------------ | ------------------------- |
| `info`    | 解释、格式、范围、数据来源   | `--sd-info` / `--sd-primary-soft`    | 无                        |
| `warning` | 需要警惕的后果、非常规状态   | `--sd-warning` / `--sd-warning-soft` | `i-tabler-alert-triangle` |
| `error`   | 已发生的失败、必须处理的阻塞 | `--sd-error` / `--sd-error-soft`     | `i-tabler-alert-circle`   |
| `success` | 已完成的确认                 | `--sd-success` / `--sd-success-soft` | `i-tabler-circle-check`   |

- `warning`、`error`、`success` **必须**带图标。"颜色不能是区分状态的唯一方式"是硬约束，风险与失败必须有非颜色通道。
- `info` **不带**图标。它是解释性的，标题与正文已自解释，加一个 ⓘ 只是装饰，且会让页面出现一排语义为零的圆圈。
- 图标尺寸 `16px`，与首行文字基线对齐，不按外接框机械居中。
- 语义按信息的真实性质选择，不按希望获得的注意力强度选择。发现新版本是 `info` 而非 `warning`；"已保存但需重载"是待办状态而非失败。

### 行为决定载体

载体由"这条信息什么时候消失"决定，而不是由它看起来该有多重要决定。

| 行为       | 生命周期                   | 载体                               |
| ---------- | -------------------------- | ---------------------------------- |
| 就近说明   | 永久，与字段共存           | `SettingRow` description、表单反馈 |
| 条件常驻   | 由状态驱动，状态消失即消失 | `TipBox`                           |
| 页面级状态 | 整页有效，需跟随滚动       | 待处理状态条（见下）               |
| 瞬时反馈   | 数秒后自动消失             | `message`                          |
| 阻塞决策   | 用户必须选择               | `dialog`                           |

- **不使用 `n-alert`。** 它自带图标、自己的调色板与圆角，与 `--sd-*` 体系并行，且项目未对其做主题覆盖。所有场景改用上表载体。
- **不使用 `notification`。** 全站保留一个只用一处的浮层体系没有收益，瞬时反馈统一走 `message`。
- **瞬时错误不用常驻载体。** `v-if="errorText"` 挂一个 `TipBox` 会在页面留下永久红块，直到下次请求成功。查询失败走 `message.error` 或空状态；只有"重试后仍失败、且用户必须看到原因才能继续"时才用常驻 `TipBox type="error"`，且**必须带重试操作**（参考 `AsyncFieldSection`）。
- 不用 `n-card :bordered="false"` 充当说明块，那是第五种表达方式。

### 位置由信息服务的对象决定

- **字段约束** → 字段下方。不上浮到页面顶部。
- **设置组的机制解释** → 设置组标题下、子面板上方第一个元素。
- **整页前置条件或风险声明** → `PageHeader` 之下、内容之上。
- **操作后果** → 触发该操作的弹窗内，紧贴标题下方。
- **禁止在页面底部放常驻提示。** 用户读到它时操作已经做完了。只读原因应紧跟被禁用的表单，恢复说明应紧跟下载入口。

### TipBox 外观规格

```
布局    左侧 3px 实心语义色边框 + 语义色 soft 底 + --sd-radius-xs
        内边距 var(--sd-space-sm) var(--sd-space-md)
颜色    --sd-{semantic} 与 --sd-{semantic}-soft，不拼接透明度字符串
图标    warning / error / success 自动渲染，info 不渲染
        相对整个提示框垂直居中，不按首行对齐，也不用 margin 估算偏移
排版    正文 --sd-text-primary，行高 1.6，段落间距由组件提供
间距    组件自带；调用方不写 mb-4 / my-4 / mt-2 之类间距类
```

- 调用方**不再**用 `<n-text type="warning">` 包裹内容，那会造成二次着色，同一提示内文字深浅不一。
- 多行内容用 `<p>` 或块元素，不用 `<br />` 堆叠。注意块元素不能嵌在 `<p>` 内。
- 图标居中依赖提示简短。若内容长到让居中图标显得脱离文字，说明这条提示违反了「一条提示只讲一个主题」，应当拆分而不是改对齐方式。
- `TipBox` 是**内容流中的说明块**，不是通栏横幅。不要用 `n-affix` 让它脱离文档流去覆盖其他内容流元素 —— 那会导致上边缘紧贴视口、圆角在视觉上消失。

### 折叠式帮助

长篇帮助统一用 `HelpCollapse`（`TipBox type="info"` + `n-collapse`，默认标题「查看帮助」）。不要在页面内自行拼装边框、圆角与背景 —— 手写容器最容易漏掉内边距，导致文字紧贴边框。

### 待处理状态

"有改动未保存"与"已保存但需重载"是同一类状态：都表示**用户做了改动但尚未生效**，都需要一个页面级动作消解，都会在长页面里滚出视口。因此**共用同一套视觉载体**，仅由标签与按钮区分动作。

区别只在一处：**未保存参与路由守卫**（离开会丢数据），**待重载不参与**（已保存，离开无损失）。

注册方式：

```ts
useUnsavedChanges('scope-name', { label, dirty, save, saving, canSave, discard, confirmMessage });
usePendingReload('scope-name', { label, pending, reload, reloading, canReload, actionText });
```

两者可同时成立，载体并列展示两条。

**「放弃改动」由 `discard` 提供，不由页面自行放按钮。** 保存是有损操作（覆盖远端值），应当有对称的撤销出口，因此凡是能把草稿恢复为远端值的页面都应传 `discard`（通常是 `draft.resetToRemote`）。状态条据此自动显示「放弃改动」，与「保存设置」同组出现，位置与顺序全站一致。无法恢复远端值的来源不传，按钮不出现 —— 不要放一个点了不起作用的按钮。

展示规则 —— **两个载体互斥，永不同时可见**：

- `PageHeader` 声明 `:unsaved-scope="[...]"` 后，标题右侧显示状态与操作，并作为可见性锚点；
- 锚点滚出视口后，全局悬浮面板淡入接管：桌面端顶部居中悬浮，**移动端沉底通栏**（拇指可达，不与面包屑争顶部空间，含 `env(safe-area-inset-bottom)` 与 `44px` 触达高度）；
- 因为互斥，两者不可能相互遮挡，也不存在重复的保存入口。

硬性约束：

- **全站任意时刻只有一个可见的保存入口。** 页面内组件与 `PageHeader` 插槽都不得再放自己的保存、放弃或脏态文案，它们由状态条统一承载。
- 待重载时隐藏标题栏的重载按钮，由状态条承载，避免同一动作两个入口。
- 过渡只用淡入与 `8px` 位移、`160ms`，并遵守 `prefers-reduced-motion`。不做从标题旁"飞"到顶部的 FLIP 动画 —— 两个位置不同时存在，没有空间关系需要解释。
- 移动端沉底状态条会盖住页面末尾，状态成立时给内容补足底部空间。位移与淡入同时发生，读起来是一个动作。

### 文案

提示只在四种情况下存在：不可逆后果、格式约束不可推知、当前状态易误解、新概念首次解释。不满足的直接删除。

- 一条提示只讲一个主题。同时包含风险警告与恢复方式时，拆成两条。
- 风险写后果，不写形容词。"删除后无法找回"好于"请谨慎操作"。
- 同类状态全站使用同一句文案与同一标点。

## 图标

- 统一使用 Tabler Icons，并通过项目现有的 Iconify / `unplugin-icons` 接入方式引用。
- 常规界面默认使用线性图标。填充图标仅用于需要更强识别度的选中态或状态标记，并在同一组内保持一致。
- 不在同一操作组中混用不同线宽、视觉尺寸或风格的图标。
- 相同动作在不同页面使用同一个图标；相同图标不承担互不相关的语义。
- 行内和表格图标通常使用 `16px`，按钮和导航图标使用 `18–20px`。较大的图标应仅用于空状态、品牌标识等明确场景。
- 图标应与相邻文字在视觉上对齐，不能仅按外接框机械居中。
- 不为了让界面更丰富而给每个标题、字段或按钮添加图标。
- 新增图标库或自定义通用 SVG 前应先评估现有 Tabler 图标。品牌和产品专属图形可以使用自定义资源，但需与整体线条、尺寸和配色协调。

## 动效

动效用于反馈状态变化、解释空间关系和维持操作连续性，不用于展示效果。

- 按钮、悬浮和小型状态反馈通常使用 `120–180ms`。
- 弹窗、抽屉和页面局部过渡通常使用 `180–240ms`。
- 主题切换可以使用更长但仍克制的过渡，当前建议约 `500ms`。
- 优先使用透明度、颜色和小幅位移；避免大幅缩放、弹跳、旋转和持续闪烁。
- 避免对会引起大范围重排的尺寸属性做复杂动画。
- 深浅主题切换使用平滑的全局过渡；当“跟随系统”解析出的实际主题与当前主题相同时，不应触发闪屏或无意义动画。
- 必须尊重 `prefers-reduced-motion`。用户请求减少动态效果时，应关闭非必要动画并缩短必要反馈。

## 深色与浅色主题

- 所有前景、背景、边框、状态色和交互态都应通过语义化主题变量定义。
- 两种主题应保持相同的信息优先级和交互反馈。
- 品牌图标、插图和带背景的图形需要分别检查两种主题下的对比度。
- 避免在组件内部硬编码纯黑、纯白或只适用于单一主题的半透明颜色。
- 切换主题时，图标必须准确表达“浅色”“深色”和“跟随系统”三种状态，并提供悬浮说明。

## 无障碍与响应式

- 所有交互必须支持键盘操作，并提供清晰的焦点状态。
- 仅图标控件必须包含 `aria-label` 或等效的可访问名称。
- 常规桌面控件的点击区域不应小于 `32px`；移动端和关键操作建议达到 `40–44px`。
- 不仅依靠颜色传达状态、错误或选中关系。
- 在窄屏下优先保证内容和主要操作可用，再考虑保留次要信息。
- 文本缩放、长文案和本地化后，布局不应遮挡关键信息或操作。

## 滑动开关

- 滑动开关只表达立即生效的布尔状态，不用于范围、布局或模式选择；后者使用复选框、单选组或分段选择器。
- 开关轨道内不放“开启／关闭”等文字或状态图标。设置名称放在开关外部，并为开关提供等效的可访问名称。
- 所有开关的激活色、加载色与焦点环统一使用主题色；关闭状态使用中性背景，不引入独立业务颜色。
- 视觉轨道保持紧凑，桌面端仍需通过标签或容器提供足够的交互热区。开关的全圆角属于滑动轨迹所需的功能性例外。
- 页面标题已能说明设置对象时，可以直接在标题旁放置开关；语义不充分时，使用“启用…”形式的短标签，不在轨道内重复状态。

## 实现约束

### 公共组件落点

已经由公共组件承载的视觉和交互模式，新页面应直接复用，不在业务页内重新实现间距、圆角、对齐或响应式切换。

| 界面模式                   | 公共组件             | 使用边界                                               |
| -------------------------- | -------------------- | ------------------------------------------------------ |
| 页面主标题与页面级操作     | `PageHeader`         | 普通页面的唯一一级标题；不用于分区标题                 |
| 父标题与子设置面板         | `SettingCategoryBox` | 所有具有明确从属关系的设置组的唯一入口                 |
| 设置字段布局与反馈         | `SettingFieldLayout` | 由 `SettingCategoryBox` 内部统一使用；页面仅声明分栏数 |
| Schema 驱动的标准设置项    | `SettingRow`         | 作为字段布局直接子项；需要表单校验时用 `n-form-item`   |
| 查询与筛选区               | `QueryToolbar`       | 承载列表查询字段、查询和重置操作                       |
| 完整列表工作区             | `ListWorkspace`      | 统一筛选、操作、结果面板和分页的顺序与竖直间距         |
| 列表级操作栏               | `ListActions`        | 按业务语义分为左侧数据操作与右侧状态、设置操作         |
| 结果摘要与批量操作         | `ResultToolbar`      | 放在结果列表内，不代替页面级或列表级操作栏             |
| 列表容器                   | `ListPanel`          | 承载列表内工具栏与结果内容；不作为通用页面卡片         |
| 可添加多子项集合           | `RepeatableList`     | 统一子项栈、空状态与底部添加入口                       |
| 可添加多子项中的单项       | `RepeatableItem`     | 统一子项边界、启用开关、辅助操作与右上删除入口         |
| 桌面表格与移动紧凑视图     | `ResponsiveDataView` | 同一数据的两种响应式表达，保持功能等价                 |
| 响应式标签页               | `ResponsiveTabs`     | 宽屏使用标签，窄屏使用选择器，适用于同级分类           |
| 必要的提示、风险和结果信息 | `TipBox`             | 仅用于规范允许保留的辅助信息，不用作常驻 caption       |
| 可折叠的「查看帮助」       | `HelpCollapse`       | 长篇帮助的唯一入口；不在页面内自行拼装折叠容器         |
| 待处理状态与其消解操作     | `PendingActionRow`   | 由 `PageHeader` 与悬浮面板共用；页面不直接使用         |
| 可折叠的列表结果卡片       | `FoldableCard`       | 主要用于移动端或紧凑列表项，不代替普通分区或设置面板   |

- 优先使用现有的 `--sd-*` 语义变量和集中式主题配置，不在单个页面复制一套颜色体系。
- Naive UI 的通用样式应通过统一的主题覆盖维护，页面级覆盖只处理确实局部的需求。
- 可复用的布局、状态和交互模式应沉淀为共享组件或样式，避免相似页面逐渐产生差异。
- 新增视觉模式前，先检查它是否能由现有组件、变量和图标表达。
- 涉及页面视觉变更时，至少检查目标页面的浅色、深色、常用桌面尺寸和窄屏状态。
- 需要复现和记录界面时，参考 [UI 浏览器截图复现指南](ui-browser-screenshot-workflow.md)。

## 评审清单

提交 UI 变更前，确认：

- [ ] 标题和操作文案可以独立说明用途，没有重复 caption；
